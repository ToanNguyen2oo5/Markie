## Hợp đồng request/response đã cung cấp

| Mục | Quyết định |
|---|---|
| Public create ảnh | `POST /post/create-with-image`, JWT người dùng, multipart; mapping `/create-with-image` dưới context `/post` |
| Part | Đúng một `content` text UTF-8 + đúng một `image` file; không extra part, không imageUrl/fileId/owner từ client |
| Content | Bắt buộc không blank theo validation hiện có, 1–500 UTF-16; giữ nguyên text gốc |
| Image | JPEG/PNG tĩnh xác thực bằng signature/parser; tối đa 5.242.880 B, mỗi chiều 1–6.000 px, tổng <=16.000.000 px |

## File Service và lỗi từng bước

1. Post xác thực JWT, validate, duyệt text + bytes ảnh một request. AI true →
   1015, lỗi/flagged không phải boolean →1016; không File/Post/event, không retry.
2. Sau AI false, client riêng gọi trực tiếp
   `POST http://localhost:8084/file/internal/post-media` với một part `image`,
   JWT người dùng + `X-Post-Media-Internal-Secret` từ `POST_MEDIA_INTERNAL_SECRET`.
   File kiểm cả hai, owner từ JWT sub. Không relay secret browser, không dùng
   key OpenAI, không gắn credential nội bộ/JWT vào AI/Profile. Thiếu/blank
   cấu hình secret fail startup ở I05/I06, test dùng fake secret.
3. File trả 200/code1000/result metadata đúng schema image; Post kiểm metadata
   khớp bytes đã duyệt + URL thuộc base tin cậy. File fail/timeout/response sai
   →1024, không save Post/event. File dọn bytes khi metadata chắc chắn không
   commit; nếu trạng thái metadata chưa rõ thì xác minh trước cleanup. Timeout
   create không có ID: không đoán ID/retry, ghi correlation để đối soát.
4. Tạo trước Post ID và save snapshot metadata. Save thành công mới Profile
   best-effort, event Kafka và response. Kafka/Profile fail không cleanup bài/ảnh.
5. Save chắc chắn fail, xác nhận không có tham chiếu: gọi
   `DELETE /file/internal/post-media/{id}` đúng file vừa tạo, cùng JWT + secret,
   owner-only; HTTP 204 rỗng idempotent. JWT invalid →401; secret sai/owner khác
   →403 tại File. Giữ lỗi save Post theo handler hiện có (runtime catch-all
   hiện HTTP400/code9999), không refactor lỗi cũ.
6. Save không rõ: đọc primary theo Post ID tạo trước, đối chiếu owner + fileId.
   Thấy đúng → đã lưu, giữ ảnh, tiếp tục success. Read lỗi/vắng/khác mà write còn
   có thể hoàn tất → giữ ảnh để đối soát, không event khi chưa xác nhận success;
   không xóa mù theo một lần read vắng.
7. Delete bù lỗi/timeout/JWT hết hạn: giữ lỗi save gốc, log ID/correlation và loại
   lỗi đã lọc để báo mồ côi; không xóa file khác hoặc bài đã lưu. Không transaction
   nguyên tử/outbox/exactly-once; ảnh đã duyệt có thể public ngắn hạn khi save fail.

Public `GET /file/post-media/{id}` trả đúng bytes/MIME/length + nosniff, ID vắng
404. Post-media dùng namespace đĩa và collection riêng. Generic upload/download
và avatar/Saga chỉ kho cũ, không thể đọc/xóa kho mới hay chứng nhận đã duyệt.
Gateway phải chặn external `/file/internal/**`, public GET mới và vẫn để File
kiểm credential khi gọi trực tiếp. Những thay đổi runtime này thuộc I05/I06.

Khác biệt checkout cần task sau xử lý: File hiện tổng request chỉ 5MB (không đủ
overhead), Post chưa cấu hình multipart; Gateway chưa public/chặn route mới,
không có RequestSize; Vite chưa proxy `/file`. Đã cập nhật shared contract:
tổng 6 MiB, URL tuyệt đối từ backend và trách nhiệm kiểm tra routing/413 rõ ràng.
