## API cung cấp cho I04/I06

```java
// Spring component, package com.stewie.post.image
public PostImageValidator.ValidatedImage validate(List<MultipartFile> images);

// Không có constructor công khai; chỉ enclosing validator có thể tạo.
public static final class PostImageValidator.ValidatedImage {
    public byte[] bytes();       // defensive copy mỗi lần
    public String contentType(); // image/jpeg hoặc image/png xác thực
    public long size();          // byte thực tế
    public int width();
    public int height();
}

public static void PostImageMultipart.validateParts(Collection<Part> parts);
```

Value object clone bytes lúc tạo và khi trả; không setter. `toString()` chỉ có
MIME/size/chiều, không bytes/Base64/tên file client. Không serialize đối tượng này
vào response/event; I04/I05 dùng đúng bytes từ accessor, không resize/re-encode.

Validator nhận **toàn bộ danh sách file**, từ chối nhiều file trước mở stream;
null/danh sách rỗng/file rỗng →1019. Size khai báo >5.242.880 B →1020 trước mở
stream. Đọc có giới hạn tối đa MAX_BYTES+1 để phòng implementation báo sai size;
vượt →1020, size không khớp →1021. Không có Base64 trong I03.

Signature quyết định PNG/JPEG; không đọc MIME/extension client để quyết định.
MIME sai/rỗng/generic và extension sai/rỗng được nhận nếu bytes hợp lệ, theo I02.
PNG kiểm CRC và bounds của từng chunk, IHDR/IDAT/IEND, tên/reserved bit/critical
chunks, palette, chuỗi IDAT và kết thúc file; từ chối acTL/fcTL/fdAT dù ImageIO
chỉ nhìn frame đầu. JPEG kiểm marker/segment/entropy stuffing/restart và EOI,
từ chối cắt cụt, trailing bytes hoặc JPEG nối nhiều ảnh. Có test progressive JPEG.

Sau đó ImageReader xác nhận format và lấy width/height **trước** `read(0)`;
chiều <=0 →1021, chiều >6000 hoặc `(long) width * height >16_000_000L` →1022.
Chỉ một ảnh từ reader, decode phải thành công, kích thước khớp, không warning.
Reader/stream luôn đóng. Giữ nguyên toàn bộ bytes gốc.

I06 phải xác thực/content-validation trước guard, rồi truyền **tất cả**
`request.getParts()` vào `validateParts`, sau đó gọi validator bằng
`request.getFiles("image")`. Guard đếm cả image text/rỗng nên không âm thầm lấy
file đầu: >1 image →1023; thiếu image →1019; image text, duplicate/blob content,
extra parts →1021. Content nhận text field không filename, Content-Type vắng
hoặc text/plain với charset vắng/UTF-8. JSON/blob/charset khác bị từ chối.
Guard không thay validation content 1017/1018, JWT, 415 hay thứ tự lỗi của I06.
Chưa nối bất kỳ route tạo bài có ảnh nào.

## Multipart và ảnh hưởng dịch vụ hiện có

- Post: `spring.servlet.multipart.max-file-size: 5242880B`,
  `max-request-size: 6291456B`. Đơn vị byte tường minh, bao gồm đúng biên.
  Test kiểm cả MultipartConfigElement thực lẫn HTTP thật tại hai biên.
- Post/Tomcat: `server.tomcat.max-swallow-size: -1`. Cho phép drain/discard body
  của upload đã bị từ chối để trả đầy đủ 413, tránh reset kết nối ở request
  tổng >6 MiB. Đây không phải nới giới hạn nhận file/request; phần vượt không
  được đưa vào validator/AI. Đổi lại Tomcat có thể tiếp tục đọc bỏ body lớn;
  I05/I06 cần giới hạn transport/proxy trước Post khi mở route ngoài.
- Advice bắt MaxUploadSizeExceededException trước catch-all, trả envelope chỉ
  `code,message` từ enum; MultipartException hỏng trả1021. Không đổi catch-all cũ.
  Test HTTP thật xác nhận không thành400/9999 và không lộ cause/path/body.
- Đã đối chiếu Gateway: route Post/File giữ context, chưa có RequestSize; không
  có cấu hình giới hạn upload thấp hơn ở Gateway. Không sửa Gateway ở I03;
  I05/I06 vẫn phải bổ sung và kiểm chứng giới hạn/413, routing và bảo vệ internal.
- File vẫn file5MB/request5MB; Profile avatar cũng file5MB/request5MB. Luồng
  avatar đi qua Profile, Redis/Kafka Saga rồi FileService.storeBytes, generic
  upload dùng File multipart riêng. Không thay các giới hạn/luồng này trong I03.
  Theo phân công I02, I05 phải nâng tổng request File lên6291456B, giữ file5242880B
  trước khi dùng post-media. Chưa thể kết luận ảnh5MiB đi xuyên Gateway/File đạt.
- JSON `/post/create` không dùng multipart; 101 ca hồi quy liên quan tiếp tục đạt.
