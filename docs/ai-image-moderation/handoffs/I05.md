## Endpoint và request/response

Context File là `/file`; controller không lặp lại context.

| Endpoint đầy đủ | Hợp đồng |
|---|---|
| POST `/file/internal/post-media` | JWT hợp lệ + `X-Post-Media-Internal-Secret`; multipart đúng một file `image`, không owner/field phụ; HTTP200/code1000/result sáu trường bên dưới |
| DELETE `/file/internal/post-media/{id}` | Cùng hai credential, owner từ JWT; HTTP204 body rỗng cho ID hợp lệ không tồn tại/đã xóa cùng owner; khác owner403 |
| GET `/file/post-media/{id}` | Public raw bytes; MIME parser xác thực, Content-Length đúng, nosniff, Content-Disposition inline, Cache-Control no-store; không thấy/ID sai404 |

```json
{"code":1000,"result":{"fileId":"12345678-1234-4123-8123-123456789abc","url":"http://localhost:8888/file/post-media/12345678-1234-4123-8123-123456789abc","contentType":"image/png","size":12345,"width":800,"height":600}}
```

Ví dụ metadata minh họa, không ảnh/token thật. JWT thiếu/sai401; secret thiếu/sai
hoặc khác owner403. File có code nội bộ1025/403,1026/404; client Post không relay
body đó, chỉ AppException POST_MEDIA_STORAGE_UNAVAILABLE1024/503 không cause.
Validation File dùng1019–1023 theo ý nghĩa I02 nhưng message nội bộ tiếng Anh.

## Cấu hình backend

Chỉ là placeholder cho môi trường backend, không đưa vào frontend hay Git:

```text
# Cả Post và File: cùng một credential riêng, bắt buộc, không phải key OpenAI.
POST_MEDIA_INTERNAL_SECRET=<INTERNAL_SECRET_PLACEHOLDER>

POST_MEDIA_PUBLIC_BASE_URL=http://localhost:8888/file/post-media
# Chỉ Post: gọi trực tiếp File, không qua Gateway.
POST_MEDIA_FILE_BASE_URL=http://localhost:8084/file
# Chỉ File: root tách rời generic app.file.storage-dir.
POST_MEDIA_STORAGE_DIR=<ABSOLUTE_DEDICATED_POST_MEDIA_DIRECTORY>
```

File default root `C:/uploads-post-media`, generic vẫn `C:\uploads`; các test
ghi đè bằng temp. Không dùng root lồng nhau hoặc root có symlink/junction/alias.
Thiếu/blank/unresolved secret khiến bean fail startup ở cả hai backend, kể cả
khi chưa dùng FileClient; không có chế độ bỏ auth. URL tin cậy yêu cầu HTTPS
ngoài localhost, path base `/file` hoặc `/file/post-media`, không query,
fragment, user-info hoặc trailing slash. Ngoài local cần đường nội bộ được bảo
vệ; I05 không thiết lập TLS/hạ tầng.

## Ownership, namespace và cleanup

- File lấy owner từ authentication name mặc định `sub` của JWT đã được resource
  server kiểm lại. Secret được so sánh bằng MessageDigest.isEqual. Raw parts
  phải đúng một file image; ownerId request không được sử dụng.
- Collection `post_media` và root riêng; generic/Saga vẫn `file_mgmt` và root
  cũ. Generic lookup không tìm kho mới; disk guard từ chối path đi ra ngoài,
  subdirectory và symlink/alias. Public post-media chỉ lookup collection mới.
- ID/path do server sinh; path flat UUID, CREATE_NEW không overwrite, mở file
  NOFOLLOW_LINKS; không sử dụng original filename. Không có update endpoint.
- Ghi bytes rồi `insert` metadata. Lỗi từ chối chắc chắn (DataIntegrityViolation
  hoặc InvalidDataAccessApiUsage) dọn đúng file vừa tạo; collision không xóa
  file cũ. Cleanup fail chỉ log fileId, trả storage error đã lọc.
- Lỗi write chưa rõ: tra theo ID để ghi nhận metadataPresent; vẫn giữ bytes dù
  read vắng/lỗi vì write có thể hoàn tất sau đó. Log ID để đối soát; không
  claim transaction nguyên tử. Chưa có worker thu gom file mồ côi.
- Delete xác minh owner trước đụng disk, xóa bytes rồi save tombstone. Nếu save
  lỗi, retry có thể xóa file đã vắng rồi lưu lại tombstone. Giữ owner sau xóa
  để retry khác owner vẫn403. ID hợp lệ vắng204; ID sai cú pháp404, không lookup.
- Validator File là mirror I03 với cùng fixture/test, giữ byte gốc, signature,
  PNG CRC/APNG/chunks và JPEG marker/frame/truncation, metadata trước decode;
  tối đa5MiB,6000 mỗi chiều,16 triệu pixel. Khi đổi validator phải đồng bộ hai
  service và test; chưa tạo shared module vì các service Maven độc lập.
